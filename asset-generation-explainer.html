Technical note · Down Syndrome Education International

Image and audio pipelines for teaching materials, and how the models were chosen

Two systems I built at Down Syndrome Education International. An image pipeline generates photographic teaching images for a 500-word early-vocabulary programme, three complexity levels per word; an audio pipeline produced 4,307 spoken clips of words and sentences across 10 English accents. Both are evaluation harnesses first and production pipelines second: the point was to decide which model and which settings to trust, with evidence, before spending at scale.

4,307 audio clips · 10 English accents · ~600 images · 389 offline tests · Images in production · no claim about image quality

The accessibility requirement

Children with Down syndrome commonly have reduced contrast sensitivity and lower visual acuity, so figure/ground separation decides whether an image teaches anything. The style presets therefore pick the background against the subject: off-white behind mid-toned or dark subjects, and a definite mid-grey whenever anything named in the picture is white, cream or pale. The object keeps its true colour; the background moves. That rule is what stops a white bath or a white nappy dissolving into the backdrop.

Related rules were earned from real failures. The object has to be the prototype a teacher would hold up: a panelled ball, not a red sphere, because the seams carry the curvature independently of shading, and shading is the first cue lost to reduced contrast sensitivity. Where a child's own version of a thing exists, the image shows it: a velcro shoe, not a men's brogue. And tense has to be visible, since "eat", "eating" and "ate" are drawn identically unless the past form is described by its aftermath.

Four layers of specification

Rules like those cannot live in a one-off prompt, so the specification is a system rather than prompt tinkering. Four layers, broadest to narrowest:

style presets // composition and difficulty, applied to every image
master prompt · ~2,500 words // content rules that apply to every word
subject glossary // canonical description + approved reference photograph per recurring subject, so the same teddy appears in every image rather than a new one each time
per-word context · one line per word // which sense of the word, and for abstract words what the picture actually shows

The routing is the point. A single wrong image gets a glossary fix; a whole class of wrong images gets a master-prompt rule, which then applies to the hundreds of words not yet generated.

How the models were chosen

The voices came out of a blind A/B listening arena: pairs of clips judged blind, with Bradley–Terry ranking and bootstrap confidence intervals over the outcomes. It compared four commercial text-to-speech providers across American, British and Irish English. The scorer reports 90% bootstrap intervals, the probability that each configuration ranks first, and which configurations are statistically indistinguishable from the leader, so a thin ranking reads as thin.

One methodology bug was found and fixed: tie-credit. First-place credit was going to whichever configuration happened to sort first, which invented leaders out of dead heats. The arena also locks the vote buttons until both clips have finished playing, as a protocol safeguard.

The honest limit: for short child-vocabulary phrases, many voices are genuinely hard to tell apart, so a lot of comparisons end in ties and the middle of the ranking stays unresolved. A second listener would be worth more than more pairs from the same one.

Cost and reruns

A batch-inference integration halved the unit cost of image generation, verified end to end, and turned out to be faster than the rate-limited synchronous path: 294 images in about 25 minutes, against about 45. Reruns are idempotent by request hash, so a rerun bills only for what changed, and the plan table marks in yellow any image that would be replaced, because the expensive silent mistake is re-drafting a brief and invalidating approved work.

A local open-weight image model was evaluated and rejected for this specification. It has a 256-token prompt limit, against presets of roughly 363 tokens, so it silently truncated them. That looked like a model ignoring instructions, and was really a model that never saw them.

Failure modes worth knowing

Safety classifiers refuse legitimate children's material. An affectionate parent-and-child image was refused at the output stage; a near-identical one passed. The difference was wording: the refused brief described the physical contact, which reads to a classifier the way it reads on the page. Rewritten toward the relationship and the setting, it passed first time. Close crops of bare feet are the same class of problem, refused as a category whatever the intent; the fix is to pull the camera back. The refusal rate is about 2%.

The drafting model degrades on long lists. On a single 100-item call it echoed its own classification into the word field for 87 of them. Nothing downstream noticed, because only the ID was validated. And since filenames derive from the word, dozens of images would have written to the same handful of paths and silently overwritten each other after being paid for. Fixed by chunking, and by never trusting the model's echo of an input the pipeline already knows.

Retrieval does not scale the way generation does. An 828-image batch produces a 3.46 GB results file with the images base64-embedded and no per-image URL, which the CDN repeatedly failed to serve. Submitting in roughly 250-image chunks gives the same price and speed with far less retrieval risk.

Cancelling a batch preserves the results already completed. The provider docs do not say either way, so it was measured: a ten-image submission, cancelled with nine complete, and all nine were collected. That later let a stalled 828-image batch be cut loose without losing the finished work.

What isn't done

  • Quality reviewBarely started. About a dozen images have been looked at individually, and the automated vision verifier has run on none of them. No claim is made about image quality.
  • Known defectsTwo real ones found in that handful: unnamed props drift pale, a leak from the contrast rule; and transparent subjects such as a glass of water take the background's tone and disappear.
  • Contrast metricThe repo's own contrast metric is not trustworthy: two of its three numbers are artefacts, documented in the module. It reported a large failure count on a batch where the true number was unknown and far smaller.
  • CoverageThe image set is still in production, not finished.

Build

Both pipelines sit behind one CLI, asset-lab, with subcommands like image generate, items from-xlsx and review build. The behaviour described above is covered by 389 offline tests (186 + 203 across the two suites).
