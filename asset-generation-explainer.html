Technical note · Down Syndrome Education International

Image, audio and video pipelines for teaching materials, and how the models were chosen

One production system I built at Down Syndrome Education International, in three parts. An image pipeline generates photographic teaching images for an early-vocabulary programme: words, phrases, sentences and a set of recurring named characters. An audio pipeline reads the curriculum’s 3,407 items aloud in four English accents, two voices each. A video pipeline holds the prompts for short verb clips and files the clips people make from them. Behind all three sits the route from a generated file to a draft asset in the charity’s catalogue. Each part is an evaluation harness first and a production pipeline second: the point was to decide which model and which settings to trust, with evidence, before spending at scale.

7,351 images in the first production set · 3,407 curriculum items · four English accents shipped · 23,846 draft assets reconciled · Images in production · no claim about image quality

The accessibility requirement

Children with Down syndrome commonly have reduced contrast sensitivity and lower visual acuity, so figure/ground separation decides whether an image teaches anything. The style presets therefore pick the background against the subject: off-white behind mid-toned or dark subjects, and a definite mid-grey whenever anything named in the picture is white, cream or pale. The object keeps its true colour; the background moves. That rule is what stops a white bath or a white nappy dissolving into the backdrop.

Related rules were earned from real failures. The object has to be the prototype a teacher would hold up: a panelled ball, not a red sphere, because the seams carry the curvature independently of shading, and shading is the first cue lost to reduced contrast sensitivity. Where a child’s own version of a thing exists, the image shows it: a velcro shoe, not a men’s brogue. And tense has to be visible, since "eat", "eating" and "ate" are drawn identically unless the past form is described by its aftermath.

Four layers of specification

Rules like those cannot live in a one-off prompt, so the specification is a system rather than prompt tinkering. Four layers, broadest to narrowest:

style presets // composition and difficulty, applied to every image
master prompt · ~2,500 words // content rules that apply to every word
subject glossary // canonical description + approved reference photograph per recurring subject, so the same teddy appears in every image rather than a new one each time
per-word context · one line per word // which sense of the word, and for abstract words what the picture actually shows

The routing is the point. A single wrong image gets a glossary fix; a whole class of wrong images gets a master-prompt rule, which then applies to the hundreds of words not yet generated.

How the models were chosen

The voices came out of a blind A/B listening arena: pairs of clips scored with Bradley–Terry ranking and bootstrap confidence intervals over the outcomes. It compared four commercial text-to-speech providers across American, British and Irish English. The scorer reports 90% bootstrap intervals, the probability that each configuration ranks first, and which configurations are statistically indistinguishable from the leader, so a thin ranking reads as thin.

One methodology bug was found and fixed: tie-credit. First-place credit was going to whichever configuration happened to sort first, which invented leaders out of dead heats. The arena also locks the vote buttons until both clips have finished playing, as a protocol safeguard.

The limit: for short child-vocabulary phrases, many voices are hard to tell apart, so a lot of comparisons end in ties and the middle of the ranking stays unresolved. A second listener would be worth more than more pairs from the same one.

Choosing a voice was not the end of it. The same speed setting produces different paces from different voices, and one provider’s voices vary by up to a tenth between renders at identical settings, so pace was settled by calibration: render, measure the audible speech with the silence trimmed, re-solve, and render again until each voice is inside a tolerance. Phrases and sentences take a slower read than single words, and that correction is held per voice. Eight accents were screened to sixteen voices; four accents shipped and four are parked, with the reasons recorded beside the manifests so a decision can be re-run rather than re-argued.

Cost and reruns

A batch-inference integration halved the unit cost of image generation, verified end to end, and turned out to be faster than the rate-limited synchronous path: 294 images in about 25 minutes, against about 45 minutes on the synchronous path. Reruns are idempotent by request hash, so a rerun bills only for what changed, and the plan table marks in yellow any image that would be replaced, because the expensive silent mistake is re-drafting a brief and invalidating approved work.

A local open-weight image model was evaluated and rejected for this specification. It has a 256-token prompt limit, against presets of roughly 363 tokens, so it silently truncated them. That looked like a model ignoring instructions, and was really a model that never saw them.

Video: the prompt is the source of truth

The third modality is short clips that teach verbs: a toddler brushing, eating, sleeping. The first attempt went through the video model’s API, and the same prompt that produced a clean clip in the model’s own web tool failed on every API tier: two toothbrushes, broken physics, foam everywhere. Two differences were never controlled, clip duration and the tool’s own prompt rewriting, so the cause is open. The decision was not to wait for it. Clips are made by hand in the tool, and the pipeline does the rest.

The rest is this. The manifest holds every prompt with its shot size, the decision behind the wording and a status of validated, draft or blocked, where absent approval counts as draft. The paste-sheet a person works from is rendered from the manifest, and a check fails when it is stale, because the previous hand-written sheet had drifted on four of the eight validated verbs without anything noticing. An ingest command files a downloaded clip where a generated one would go, with the same provenance sidecar, so review and verification work unchanged. Duration and resolution are read off the file with a small MP4 parser rather than copied from a request the tool never received, and the provenance names the tool and leaves the model tier empty rather than guess it.

Prompts are drafted for about sixty verbs across five sets; eight are validated. One verb is blocked on a decision about which sign vocabulary to teach, and a few are flagged in advance as likely failures: a very young child in water, and a book, which is made of text.

From a disk to the catalogue

Audio was the first modality to reach the charity’s asset catalogue, so its conventions set the precedent. The route is audit, repair, upload, reconcile. Audit is mechanical first: clipping, silence, truncation and pace outliers are measured over a batch, and two clips with the same content hash are flagged, because that is the same audio filed under two words. Then it is by ear, because the measurements cannot hear a mispronunciation.

A defect found by ear is fixed by promoting a repaired take, never by regenerating. Promotion stamps the fix’s provenance with what it replaced; without that stamp the next production run renders the defect back over the fix and reports success. Upload consumes an approved inventory, never a directory scan, since a scan ships whatever is on the disk: a superseded clip, a stray probe, a voice that failed review. Every inventory row carries its content hash, which is also the key the reconciler joins on, so completeness and correctness are checked against the ledger after every run.

Two findings changed the code. Stalls between uploads were hung TCP connects, near-exact multiples of the operating system’s connect timeout, and one run spent most of its wall clock in them; calls now die at twenty to thirty seconds. And an expired session is not a transient failure: a retry policy built for those hung routes spent seven hours retrying a dead credential and blamed every row it reached. The run now stops, records nothing for the untried rows, and prints the sign-in command.

Four accents, 23,846 draft assets, reconciled clean. Nothing is published. That is a separate human decision.

Failure modes worth knowing

Safety classifiers refuse legitimate children’s material. An affectionate parent-and-child image was refused at the output stage; a near-identical one passed. The difference was wording: the refused brief described the physical contact, which reads to a classifier the way it reads on the page. Rewritten toward the relationship and the setting, it passed first time. Close crops of bare feet are the same class of problem, refused as a category whatever the intent; the fix is to pull the camera back. The refusal rate is about 2%.

The drafting model degrades on long lists. On a single 100-item call it echoed its own classification into the word field for 87 of them. Nothing downstream noticed, because only the ID was validated. And since filenames derive from the word, dozens of images would have written to the same handful of paths and silently overwritten each other after being paid for. Fixed by chunking, and by never trusting the model’s echo of an input the pipeline already knows.

Retrieval does not scale the way generation does. An 828-image batch produces a 3.46 GB results file with the images base64-embedded and no per-image URL, which the CDN repeatedly failed to serve. Submitting in roughly 250-image chunks gives the same price and speed with far less retrieval risk.

Cancelling a batch preserves the results already completed. The provider docs do not say either way, so it was measured: a ten-image submission, cancelled with nine complete, and all nine were collected. That later let a stalled 828-image batch be cut loose without losing the finished work.

What isn’t done

  • Image qualityNot reviewed systematically. The automated vision verifier has not been run over the set, so no claim is made about image quality.
  • Known defectsTwo real ones found in that handful: unnamed props drift pale, a leak from the contrast rule; and transparent subjects such as a glass of water take the background’s tone and disappear.
  • Contrast metricThe repo’s own contrast metric is not trustworthy: two of its three numbers are artefacts, documented in the module. It reported a large failure count on a batch where the true number, never counted exactly, was far smaller.
  • CoverageThe image set is still in production, not finished.
  • VideoMost drafted prompts have never been generated, and the rules they follow were learned by getting the first set wrong, so expect rejections.
  • AudioFour accents are parked, and a handful of clips ship as accepted with reservation: the least bad of several takes, on an open list.

Build

All of it sits behind one CLI, asset-lab, with subcommands like image generate, audio calibrate, video prompts and review build. The behaviour described above is covered by about 650 offline tests across the two code bases (467 + 186).
